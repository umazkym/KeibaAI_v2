# KeibaAI_v2 モデル性能比較分析レポート

**作成日:** 2025年11月23日
**作成者:** AIアシスタント (Gemini)

## 1. エグゼクティブサマリー

本レポートは、KeibaAI_v2プロジェクトで生成された4つの主要な予測モデルの性能を比較分析した結果をまとめたものです。

2024年のレースデータを対象としたバックテストの結果、**`mu_phase_d_fixed` モデルが回収率76.74%という最も優れた性能**を示しました。

この性能向上は、**データリーク（未来情報の不正利用）によるものではなく、特徴量生成過程のバグが修正されたことで、これまで利用できていなかった約50個の強力な特徴量が初めて学習に組み込まれたため**であると結論付けられます。`mu_phase_d_fixed`は、プロジェクトの設計通りの特徴量をフルに活用できた、最初の正常なモデルであると言えます。

## 2. モデル別 回収率（ROI）比較

`evaluate_model.py` を用いて、各モデルの単勝AI本命馬買い（100円/レース）戦略での2024年通期バックテストを実施しました。

| モデル名 | 回収率 (ROI) | 備考 |
| :--- | :--- | :--- |
| **`mu_phase_d_fixed`** | **76.74%** | **最も高い回収率** |
| `complete_model_optimized_2024` | 72.97% | |
| `complete_model_2024` | 68.61% | |
| `mu_model_20241122_final` | 68.61% | |

## 3. モデル間の差異 詳細分析

各モデルの名称と性能差の背景には、開発経緯と技術的な違いが存在します。

### 3.1. `mu_model` と `complete_model` の役割

まず、モデル名の基本的な違いについて説明します。

- **`mu_model`**: 馬の絶対的な能力（予想タイムなど）を予測する、LightGBMで訓練された**コア予測モデル（μ）**です。本プロジェクトの予測性能の根幹を担います。
- **`complete_model`**: 実際のシミュレーションと投資判断に必要な全てのコンポーネントを内包した**完全な予測システムパッケージ**です。具体的には、コアな予測を担うμ（mu）モデルに加え、予測のばらつきをモデル化する**σ（sigma）モデル**と、レースの"荒れやすさ"をモデル化する**ν（nu）モデル**が含まれています。

### 3.2. バグ修正がもたらした性能差 (`mu_model_20241122_final` vs `mu_phase_d_fixed`)

両モデルの劇的な性能差（68.61% vs 76.74%）は、**特徴量生成スクリプトのバグ**に起因します。

- **`mu_model_20241122_final` (バグありモデル)**:
  このモデルの学習時、`keibaai/src/features/advanced_features.py`内で、約50個の高度な特徴量（"Phase D" 特徴量）を追加する処理にバグがありました。データフレームのカラム名が不一致（例: `place` と `venue`）だったため `KeyError` が発生し、**これらの高度な特徴量が一切追加されないまま**学習データが生成されていました。

- **`mu_phase_d_fixed` (バグ修正済みモデル)**:
  モデル名の "fixed" が示す通り、このモデルは上記バグが修正された後に学習されました。その結果、**以下の新規特徴量が初めて学習データに正しく含まれ**、これが性能向上に直接的に寄与しました。

#### `mu_phase_d_fixed`で新たに追加された主な特徴量

2つのモデルの特徴量リストを比較した結果、`mu_phase_d_fixed`には以下のカテゴリに分類される**47個**の新しい特徴量が追加されていることが確認されました。

**カテゴリ1: コース・競馬場との相性に関する特徴量**
- `bracket_avg_finish`: 枠番ごとの平均着順
- `jockey_[競馬場名]_win_rate`: 騎手ごとの競馬場別勝率（例: `jockey_東京_win_rate`）
- `trainer_[競馬場名]_win_rate`: 調教師ごとの競馬場別勝率

**カテゴリ2: 血統（父・母父）に関する特徴量**
- `sire_avg_prize`: 父馬の産駒平均獲得賞金
- `sire_[距離カテゴリ]_avg_finish`: 父馬の産駒の距離別平均着順（例: `sire_mile_avg_finish`）
- `sire_[競馬場名]_avg_finish`: 父馬の産駒の競馬場別平均着順

**カテゴリ3: 逃げ・先行などの脚質に関する特徴量**
- `nige_ratio`: 過去レースでの逃げた比率
- `senko_ratio`: 過去レースでの先行した比率

これらの特徴量は、それまでのモデルが持っていなかった「**その馬が、今回のレース条件（競馬場、距離、枠順）で走りそうか**」という新しい視点をモデルに与え、予測精度を大きく向上させたと考えられます。

### 3.3. `complete_model_optimized_2024` の「最適化」について

`complete_model_2024` (ROI 68.61%) と `complete_model_optimized_2024` (ROI 72.97%) を比較したところ、両者の特徴量リストに差はありませんでした。

このことから、「最適化（optimized）」とは、**特徴量の選択ではなく、LightGBMモデルのハイパーパラメータ（学習率、木の深さなど）をチューニングした**ことによる性能改善であると強く推測されます。

## 4. データリークの可能性に関する検証

調査の結果、**データリークが発生している可能性は極めて低い**と判断します。

- **設計思想としての対策**: 設計書`CLAUDE.md`に「最終オッズを訓練に使わない」と明記されており、開発チームはリークのリスクを当初から認識していました。
- **コードレベルでの対策**: 特徴量生成や評価スクリプト内でも、過去のデータのみを使用するようにフィルタリング処理が記述されており、意図的に未来の情報を遮断する設計になっています。
- **性能向上の合理的説明**: `mu_phase_d_fixed`の性能向上は、前述の通り「バグ修正による特徴量の追加」という明確な技術的理由で説明が可能です。

## 5. 結論と推奨

今回の分析により、`mu_phase_d_fixed`が最も信頼性が高く、かつ高性能なモデルであることが明らかになりました。この優位性は、データリークのような不正な要因によるものではなく、**開発プロセスの改善とバグ修正によって、モデルが本来持つべき特徴量を完全に利用できるようになった**ことに起因します。

今後の予測や投資シミュレーションにおいては、この**`mu_phase_d_fixed`モデル系統をベースとして利用することを強く推奨します**。
