# タイム・指標の補正に関する分析と提案 (Ver.3)

ユーザー様のご指摘通り、厳密な「同一グループ（日時・条件一致）」は発生頻度が低く、それだけに頼ると比較が困難です。
一方で、**「2020年～2025年の約5年間の膨大なデータ」**があることは大きな強みです。
このデータを活用し、**「個別のレース条件の違いを、5年間の統計データを用いて吸収・正規化する」**アプローチを提案します。

## 1. コンセプト: 5年基準の統計的正規化 (Statistical Standardization)

「そのレースのメンバー内」での比較ではなく、**「過去5年間の同条件レース全体」**を母集団として、その中での相対評価（偏差値）を算出します。
これにより、いつ、どこの競馬場で走った記録であっても、**「偏差値 (指数)」**という共通の物差しで比較が可能になります。

## 2. 実装詳細: 「同条件」の定義と正規化ロジック

「同条件」をどこまで細かく定義するかで、精度の高さとサンプル数の確保のバランスが決まります。
5年間のデータを最大限活用するため、以下の階層構造で定義します。

### A. 基準統計グループ (Base Statistics Group)
偏差値（指数）の算出基準となる母集団です。以下の4つのキーが完全に一致するレースを「同条件」と定義します。

1.  **競馬場 (Venue)**: 東京、中山、京都、阪神... (全10場)
2.  **距離 (Distance)**: 1200m, 1600m, 2400m...
3.  **トラック種別 (Track Type)**:
    *   **芝**: 内回り / 外回り / 直線
    *   **ダート**: 通常
    *   **障害**: 芝 / ダート / バンケット有無
    *   ※「内回り」と「外回り」はコース形状が全く異なるため、明確に区別します。
4.  **馬場状態 (Condition)**: 良、稍重、重、不良 (4区分)

**※レースレベル（クラス）の扱いについて**:
あえて**「クラス（未勝利、1勝クラス、G1など）」はグループ化の条件に含めません**。
*   **理由**: クラスごとに基準を変えてしまうと、「未勝利戦の偏差値50」と「G1の偏差値50」が同じ数字になってしまい、強さの比較ができなくなるためです。
*   **効果**: 全クラス混合の平均を基準（50）とすることで、**「G1級の馬なら指数70～80」「未勝利級なら指数40～50」**といったように、**絶対的な強さ**を数値で比較できるようになります。「下級条件なのにG1級の指数を出した馬」を発見できるのが最大のメリットです。

**※コース区分 (A/B/C/D) の扱いについて**:
Aコース～Dコースの違いは、主に「内柵の位置」による幅員とコーナーの半径の変化です。
これらを全て別グループにするとサンプル数が分散しすぎる（例：「東京芝2400m 重 Cコース」は5年で数回しかない可能性がある）ため、**基準統計グループには含めず、後述の「馬場差」で吸収**します。

### B. 指数の計算ロジック

各馬の走破タイム $T$ に対して、以下の手順で指数を算出します。

1.  **基準値の取得**:
    *   そのレースの `(競馬場, 距離, トラック種別, 馬場状態)` に一致する過去5年間の全レースデータを取得。
    *   平均タイム $\mu$ と標準偏差 $\sigma$ を算出。

2.  **タイム指数 (Time Index) の算出**:
    $$ \text{TimeIndex} = 50 + 10 \times \frac{\mu - T}{\sigma} $$
    *   平均と同じなら50。
    *   平均より速い（タイムが小さい）ほど数値が大きくなる。
    *   通常、30～80程度の範囲に収まります。

3.  **馬場差 (Track Bias) の算出**:
    *   その日の全レース（または同トラック種別のレース）の平均タイム指数を算出。
    *   もし平均指数が `55` なら、「普段より速いタイムが出やすい高速馬場 (-0.5σ相当)」と判定。
    *   この「当日の平均指数 - 50」を馬場差として表示、または指数から差し引いて補正します。

### C. 具体的なデータ構造イメージ

`generate_race_report.py` 内で、事前に以下の辞書を作成しておきます。

```python
# 基準統計テーブル (Lookup Table)
stats_lookup = {
    # (競馬場, トラック種別, 距離, 馬場状態): (平均タイム, 標準偏差)
    ("東京", "芝・左・外", 1600, "良"): (93.5, 1.2),  # 1:33.5
    ("東京", "芝・左・外", 1600, "重"): (95.2, 1.5),  # 1:35.2
    ("中山", "芝・右・内", 1200, "良"): (68.4, 0.8),  # 1:08.4
    ...
}
```

### D. 補正の適用範囲

*   **コース替わり (A/B)**: 「馬場差」として数値化されます（Aコースで内が有利なら、全体のタイム指数が上がり、馬場差がプラスに出る）。
*   **開催時期**: 「馬場状態（良/重）」で大枠は捉えつつ、季節ごとの微妙な差も「馬場差」として可視化されます。
*   **展開**: 別途 `RPCI` (ペース指数) で評価します。

この定義により、**「コース形状（内/外）と馬場状態（良/重）までは厳密に区別し、それ以外の微差（A/Bコース、季節）は当日補正（馬場差）で対応する」**という、実用的かつ統計的に妥当なラインを実現します。

## 3. 分析・実装フロー

このアプローチであれば、`GroupNo` が一致しなくても以下のように分析できます。

1.  **タイム指数を見る**: まず絶対的なパフォーマンスレベルを確認（例：指数60以上なら重賞級）。
2.  **馬場差とRPCIを見る**: その指数が出た背景を確認。
    *   「高速馬場で前残り（RPCI高）だったから指数が高いのか？」
    *   「タフな馬場でハイペース（RPCI低）を耐えて指数が高いのか（＝本当に強い）？」

## 4. 必要なデータ処理
お手元の `races.parquet` (2020-2025) を用いて、以下の「基準統計テーブル」を事前作成します。

*   **キー**: `競馬場`, `コース区分(芝/ダ)`, `距離`, `馬場状態(良/稍/重/不)`
*   **値**: `平均タイム`, `タイム標準偏差`, `平均3F`, `3F標準偏差`

これを `generate_race_report.py` で読み込み、各レースのタイムを即座に指数変換して出力します。
