# μモデル ROI 100%超えへのロードマップ (絞り込みなし)

## 1. 現状分析と課題 (v2.8)
- **現状**: v2.8は「1番人気」を100%の確率でTop1に選出しています。
- **結果**: 的中率は高い(26.9%)ものの、ROIは「1番人気の平均的な回収率(約75-80%)」に収束しており、79.44%にとどまっています。
- **根本原因**:
    - 学習目的が「正解すること（的中率最大化）」に偏りすぎている。
    - オッズ加重を行っても、ノイズの多い穴馬を当てるより、堅実な人気馬を当てる方が損失関数（LogLoss）を下げやすいため、モデルが「安全策」をとっている。
- **結論**: 「絞り込みなし（全レース参加）」でROI 100%を超えるには、**「人気馬が過剰人気で飛ぶレース」を見抜き、代わりに「期待値の高い穴馬」をTop1に指名する** 必要があります。

## 2. 戦略コンセプト: "From Accuracy to Value"
「的中率（Accuracy）」ではなく「期待値（Value）」を直接最大化するモデルへ転換します。

### 目標
- **Top 1 指名馬の単勝回収率 > 100%**
- 1番人気を盲目的に選ぶのではなく、リスクを取ってでも高配当を狙う挙動へシフトする。

## 3. 具体的な実装アプローチ

### Phase 1: 学習目的の根本的変更 (Learning to Rank)
現在の「2値分類（勝つか負けるか）」から、「ランキング学習（どの馬が最も儲かるか）」へ移行します。

- **手法**: LightGBM `lambdarank`
- **変更点**:
    - **ラベル**: 0 or 1 ではなく、**「オッズ（配当）」** をラベルの重み（Gain）として使用する。
    - **効果**: 「1.5倍の勝ち」よりも「10倍の勝ち」を上位にランク付けした方が、モデルの評価スコアが劇的に上がるように設計する。これにより、モデルは「小さな当たり」を捨てて「大きな当たり」を狙いに行くようになります。

### Phase 2: 損失関数のカスタム化 (Value-Weighted Loss)
標準のLogLossではなく、ROIに直結するカスタム損失関数を導入します。

- **カスタム目的関数**:
    - 予測が外れた場合のペナルティは一定だが、**当たった場合の報酬（勾配）をオッズに比例させる**。
    - `Gradient = (Pred - Target) * Odds` のようなイメージ。
    - これにより、高配当馬の予測を外すことが、低配当馬を外すことよりも「罪深い」とモデルに教え込みます。

### Phase 3: "穴馬"を見つけるための特徴量強化
人気馬と同じ特徴量（勝率、連対率など）を見ている限り、人気馬しか選べません。「人気はないが勝つ理由がある馬」を見つけるための特徴量が必要です。

1.  **激走フラグ（Change Factors）**:
    - **ブリンカー着用**: `is_blinker_changed` (初ブリンカーは激走率が高い)
    - **騎手大幅強化**: `jockey_rank_diff` (前走騎手ランク vs 今回騎手ランク)
    - **距離短縮**: `is_distance_shortened` (特に短距離戦への短縮)
2.  **不利・言い訳（Excuse Factors）**:
    - **前走の不利**: 前走で「詰まった」「出遅れた」「大外を回らされた」などの不利があった馬（テキストマイニングやコーナー通過順位から推定）。
    - **トラックバイアス逆行**: 前走が「内有利」の馬場で「外枠」だった馬など。
3.  **過剰人気判定（Overvalued Detection）**:
    - メディア露出度や新聞の印（もし取得できれば）と、実力値（スピード指数等）の乖離。

### Phase 4: アンサンブル戦略 (Specialist Models)
1つのモデルですべてを解決するのではなく、役割分担を行います。

- **Model A (堅実型)**: 従来通り的中率重視（v2.8ベース）。
- **Model B (一発型)**: 高配当重視（Ranker/Custom Loss）。
- **統合ロジック**:
    - Model Aが「この1番人気は怪しい（スコアが低い）」と判定し、かつ Model Bが「この穴馬は面白い」と判定した時、Top 1をModel Bの推し馬に入れ替える。

## 4. 実行ロードマップ (v2.9 ~ v3.0)

| バージョン | 内容 | 予想ROI | 難易度 |
| :--- | :--- | :--- | :--- |
| **v2.9** | **Learning to Rank (LGBM Ranker) の導入**。<br>ラベルゲインにオッズを使用し、高配当馬の優先順位を上げる。 | 85%~95% | 中 |
| **v3.0** | **カスタム損失関数の実装**。<br>ROI最大化を数学的に定義した損失関数で学習。 | 95%~105% | 高 |
| **v3.1** | **激走・不利特徴量の追加**。<br>穴馬の検知精度を物理的に向上させる。 | 100%+ | 高 |

## 5. ユーザーへの推奨アクション
まずは **v2.9 (Learning to Rank)** の開発に着手することを推奨します。これは既存のLightGBMフレームワーク内で設定変更により実装可能であり、最も即効性が期待できます。
