## 2. なぜ競馬AIは難しいのか - 根本的な問題認識

### 2.1 競馬AI失敗の構造的要因

```
┌─────────────────────────────────────────────────────────────────┐
│                    競馬AI失敗の構造的要因                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  【問題1】控除率の壁                                             │
│  └─ JRAが約20%を控除 → 普通に買うと回収率80%に収束              │
│  └─ 「強い馬を当てる」だけでは絶対に勝てない                    │
│                                                                 │
│  【問題2】オッズへの収束                                         │
│  └─ オッズ・人気を特徴量に入れると、予測が市場に追随            │
│  └─ 的中しても期待値が1を超えない                               │
│                                                                 │
│  【問題3】過小評価の陳腐化                                       │
│  └─ 発見した「エッジ」は他者にも発見され、すぐに消失            │
│  └─ 継続的な特徴量発見・モデル更新が必須                        │
│                                                                 │
│  【問題4】複合馬券の確率計算の困難さ                             │
│  └─ 三連単は数千通りの組み合わせ                                │
│  └─ 単一モデルでは期待値計算が不可能                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 解決方針

**核心原則：「オッズに織り込まれていない情報」だけを使う**

```python
# ❌ 使ってはいけない特徴量（市場に織り込み済み）
FORBIDDEN_FEATURES = [
    'odds',              # オッズそのもの
    'popularity',        # 人気順位
    'expected_odds',     # 予想オッズ
    'betting_fraction',  # 投票率
]

# ✅ 使うべき特徴量（市場が見落としやすい）
VALUABLE_FEATURES = {
    'hidden_ability': [
        'last_3f_rank_avg',        # 上がり3F順位（展開不利でも能力は高い）
        'best_time_at_distance',   # 同距離ベストタイム
        'class_up_performance',    # 昇級初戦での走り（過小評価されやすい）
    ],
    'aptitude_mismatch': [
        'track_type_change',       # 芝↔ダート転向
        'distance_change_ratio',   # 距離変更率
        'going_preference_score',  # 馬場状態適性スコア
    ],
    'condition': [
        'weight_change',           # 馬体重増減
        'rest_days_optimal',       # 休養日数の最適性
        'trainer_recent_form',     # 調教師近走成績
    ],
}
```

## 3. 4層ハイブリッドアーキテクチャ設計

### 3.1 アーキテクチャ概要

```
┌─────────────────────────────────────────────────────────────────┐
│                    4層ハイブリッドアーキテクチャ                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Layer 1: 能力推定層（Ability Estimation）                       │
│  ├─ 目的: 各馬の「真の能力」をスコア化                          │
│  ├─ 手法: LightGBM Ranker (LambdaRank)                          │
│  └─ 特徴: オッズ・人気を完全排除した特徴量                      │
│           ↓                                                     │
│  Layer 2: 確率変換層（Probability Calibration）                  │
│  ├─ 目的: スコアを「勝率」に正確に変換                          │
│  ├─ 手法: Platt Scaling / Isotonic Regression                   │
│  └─ 特徴: レース内で合計100%になる確率を生成                    │
│           ↓                                                     │
│  Layer 3: 着順シミュレーション層（Monte Carlo Simulation）       │
│  ├─ 目的: 全馬券種の出現確率を算出                              │
│  ├─ 手法: ハービル法 + モンテカルロ法                           │
│  └─ 特徴: 三連単の全順列確率を高速計算                          │
│           ↓                                                     │
│  Layer 4: 期待値最適化層（EV Optimization & Betting）            │
│  ├─ 目的: EV > 1.0 の馬券を抽出し、資金配分を最適化             │
│  ├─ 手法: ケリー基準 + 有効フロンティア                         │
│  └─ 特徴: リスク調整済みリターンの最大化                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 Layer 1: 能力推定層

**実装**: `LeakFreeFeatureEngineerV7` + `LGBMRanker`

**マルチタスク・ランク学習**:
- Model 1: LightGBM LambdaRank（段階的関連度）
- Model 2: LightGBM LambdaRank（単勝特化）
- Model 3: CatBoost YetiRank
- Model 4: CatBoost QuerySoftMax

**関連度ラベルの生成**:
```python
# 段階的関連度: 1着=5, 2着=4, 3着=3, 4-5着=1, 他=0
y_rel = np.zeros(len(y))
y_rel[y.values == 1] = 5
y_rel[y.values == 2] = 4
y_rel[y.values == 3] = 3
y_rel[(y.values >= 4) & (y.values <= 5)] = 1
```

### 3.3 Layer 2: 確率変換層

**手法**: Isotonic Regression + Softmax正規化

```python
# キャリブレーション後、レース内で正規化
def transform(self, scores, groups):
    raw_probs = self.calibrator.transform(scores)
    result['win_prob'] = result.groupby('group_id')['raw_prob'].transform(
        lambda x: x / x.sum()
    )
    return result
```

**評価指標**:
- Brier Score < 0.20: 合格基準
- ECE (Expected Calibration Error) < 0.05: 合格基準

### 3.4 Layer 3: 着順シミュレーション層

**ハービル法による確率計算**:

```
馬単: P(i→j) = P(i wins) × P(j wins | i won)
            = P(i) × P(j) / (1 - P(i))

三連単: P(i→j→k) = P(i) × P(j)/(1-P(i)) × P(k)/(1-P(i)-P(j))
```

**JRA控除率**:

| 馬券種 | 控除率 | 払戻率 |
|--------|-------|--------|
| 単勝 | 20% | 80% |
| 複勝 | 20% | 80% |
| 馬連 | 22.5% | 77.5% |
| 馬単 | 25% | 75% |
| 三連複 | 25% | 75% |
| 三連単 | 27.5% | 72.5% |

### 3.5 Layer 4: 期待値最適化層

**期待値計算**:
```python
EV = 確率 × オッズ × 払戻率

# オッズ調整（高オッズの過大評価を抑制）
if odds > 50:
    adjusted_odds = 30 + (odds - 50) / (1 + 0.05 * (odds - 50))
elif odds > 20:
    adjusted_odds = 20 + (odds - 20) / 2
else:
    adjusted_odds = odds
```

**ケリー基準**:
```python
# f* = (bp - q) / b
# b: 純利益倍率（オッズ - 1）
# p: 勝率
# q: 敗率（1 - p）
kelly = (b * p - q) / b
kelly = max(0, min(kelly, 1)) * kelly_fraction  # 保守的に0.25
```

## 7. LeakFreeFeatureEngineerV7実装

### 7.1 設計原則

**時点考慮型（Point-in-Time）計算**:

```
2025年6月15日のレース → 2025年6月14日以前のデータのみで統計計算
2025年6月16日のレース → 2025年6月15日以前のデータのみで統計計算
```

この原則はTrain期間だけでなく**Test期間でも同様に適用**される。

> [!CAUTION]
> **2025-12-08 重大リーク修正**: 以前のV7実装には、transform時に新規データの`finish_position`から`is_win`を計算し、累積統計に含めるバグがありました。これにより、Test期間のレース結果が累積統計にリークし、ROIが大幅に水増しされていました（265%→80%に修正）。詳細は[セクション9.11](#911-重大リーク修正2025-12-08)を参照。

**実装方法**: `cumsum() + shift(1)` パターン

```python
# 馬の累積レース数
df['horse_cum_races'] = df.groupby('horse_id')['is_win'].transform(
    lambda x: x.notna().cumsum().shift(1).fillna(0)
)

# 馬の累積勝利数
df['horse_cum_wins'] = df.groupby('horse_id')['is_win'].transform(
    lambda x: x.fillna(0).cumsum().shift(1).fillna(0)
)

# 勝率計算（最低レース数制限）
df['horse_win_rate'] = np.where(
    df['horse_cum_races'] >= min_races,
    df['horse_cum_wins'] / df['horse_cum_races'],
    np.nan
)
```

### 9.11 重大リーク修正（2025-12-08）

#### 9.11.1 発見された問題

2025-12-08の追加検証で、V7のtransformメソッドに**重大なデータリーク**が発見されました。

**問題のコード（修正前）**:

```python
# 新規データ（履歴にないもの）は実際のfinish_positionから計算
if 'finish_position' in df.columns:
    df.loc[new_mask, 'is_win'] = (df.loc[new_mask, 'finish_position'] == 1).astype(float)
    df.loc[new_mask, 'is_top3'] = (df.loc[new_mask, 'finish_position'] <= 3).astype(float)
```

**問題点**:
- Test期間のデータをtransformする際、`finish_position`（レース結果）から`is_win`を計算
- これを履歴データと結合して累積統計を計算
- 結果として、**Test期間のレース結果が累積統計にリーク**

#### 9.11.2 リークの影響度

精密リークテストの結果:

| 条件 | Test ROI | Test的中率 |
|------|----------|------------|
| 修正前（リークあり） | **265.8%** | 43.4% |
| 修正後（リークなし） | **79.2%** | 21.0% |
| finish_position隠し | 79.9% | 18.6% |
| **差分（修正後 vs 隠し）** | **-0.7%** | +2.4% |

**結論**: 修正後と隠しテストの差分が誤差範囲内（-0.7%）であることから、**リークは完全に解消**されました。

#### 9.11.3 修正内容

**修正後のコード**:

```python
# 新規データ（履歴にないもの）は is_win/is_top3 を NaN に設定
# 【重要】finish_positionからis_winを計算すると、累積統計にリークが発生するため
# 新規データの結果情報は累積統計に含めない
new_mask = df['_unique_key'].isin(new_keys)
df.loc[new_mask, 'is_win'] = np.nan
df.loc[new_mask, 'is_top3'] = np.nan
```

## 14. V8開発と過学習の克服（2025-12-08追記）

13.5節の計画に基づき、V7の限界（ROI 79%）を突破するためV8の開発を実施しました。

### 14.1 V8開発の経緯と課題

当初、計画されていた特徴量を一気に追加した「Full V8」を作成しましたが、深刻な過学習が発生しました。

**追加した特徴量（計16個）**: 母父統計、条件別統計、クラス変動、体重変動、騎手条件別統計など。

**検証結果（2025-12-08実施）**:

| モデル | Train Hit | Test Hit | Gap | Test ROI | 状態 |
|---|---|---|---|---|---|
| **Full V8** | 54.0% | 17.9% | **36.1%** | 79.7% | **深刻な過学習** |
| V7 (Baseline) | 30.2% | 20.4% | 9.8% | 84.2% | 正常・高安定 |

※V7のROIがレポート本編の79.2%より高い84.2%となっているのは、最新の検証環境でハイパーパラメータ（強力な正則化）が最適化されているためです。

### 14.2 原因特定と対策（Ablation Study）

特徴量グループごとの除外テスト（Ablation Study）および追加テスト（Forward Selection）を実施した結果、以下の事実が判明しました。

1.  **騎手条件別統計**（`jockey_venue/distance_win_rate`）が過学習の主因であり、Train性能を不正に引き上げている（学習データの丸暗記）。
2.  **クラス変動**（`class_change`, `is_class_up`など）のみが、Test ROIを明確に向上させる（V7比 +2%以上）。
3.  その他（母父、条件別、体重）は現時点ではTest ROIに寄与しないか、わずかに悪化させる。

### 14.3 V8.1（最終版）の成果

「クラス変動」関連の5特徴量のみを追加し、他の過学習要因となる特徴量を全て削除した「V8.1」を策定しました。

**V8.1の特徴量構成**:
- V7の33特徴量（基礎）
- クラス変動特徴量（`race_class`, `prev_race_class`, `class_change`, `is_class_up`, `is_class_down`）

**最終検証結果**:

| モデル | Test ROI | Test Hit | 備考 |
|---|---|---|---|
| **V8.1** | **86.4%** | 18.6% | **V7比 +2.2% 向上** |

### 14.4 結論

「クラス変動（昇級・降級）」の情報はオッズに完全には織り込まれておらず、**有効なエッジ（AIが勝てる要素）**となることが実証されました。
一方で、騎手や血統の条件別統計は、単純に追加するだけでは過学習のリスクが高いことも判明しました。

今後はこのV8.1を新たなベースラインとして開発を継続します。

## 17. V11-V13: クラス変動リークの発見と解決（2025-12-09追記）

V10.2で安定したかに見えましたが、V12マルチモデル比較検証において、Train ROIが異常に高い（200%超）問題が再浮上しました。
詳細な調査の結果、**V8で導入された「クラス変動」特徴量に重大なデータリーク**があることが判明しました。

### 17.1 リークのメカニズム

**原因**: `LeakFreeFeatureEngineerV8` の `_calc_class_change` メソッドの実装ミス。

```python
# 誤った実装（概念）
hist = self._full_history  # 全期間の履歴
last_race = hist.groupby('horse_id').last()  # 各馬の「キャリア最後」のレース情報
df = df.merge(last_race, on='horse_id')      # 全レースに「未来の最終クラス」をマージ
```

**現象**:
- 2020年の新馬戦を走る馬に対し、その馬が「将来2024年にG1に出走する」という情報が `prev_race_class` として付与されていました。
- これにより、「新馬戦なのに前走がG1（=大幅な降級）」という強力かつ虚偽のシグナルが生成され、モデルがこれを学習してしまいました。

### 17.2 V12: Point-in-Time修正

`LeakFreeFeatureEngineerV12` にて、正しい時系列順序で前走クラスを取得するように修正しました。

**検証結果**:

| モデル | Train ROI | Test ROI | Gap | 判定 |
|-------|-----------|----------|-----|------|
| **V10.2 (Leak)** | 226.1% | 86.8% | 139.4% | ❌ リークによる過信 |
| **V12 (Fix)** | **108.1%** | **79.2%** | **28.9%** | ✅ 正常化（実力値） |

Test ROIは 86.8% → 79.2% に低下しましたが、これは「バグによるぬか喜び」が解消された結果であり、79.2%こそが真の実力値です。

### 17.3 V13: 新特徴量による正当な性能向上

リークフリーとなったV12をベースに、V11で開発した5つの新特徴量（`prev_finish_category`など）を追加し、Optunaでチューニングを行った **V13** を開発しました。

**V13の特徴**:
1.  **完全リークフリー**: クラス変動のバグを修正済み
2.  **新特徴量の搭載**: 「前走大敗からの巻き返し」などを検知
3.  **Optuna最適化**: LightGBMハイパーパラメータを自動調整

**最終パフォーマンス**:

| モデル | Test ROI | Gap | 評価 |

| V12 (Fix) | 79.2% | 28.9% | ベースライン |
| **V13 (New)** | **82.8%** | **59.6%** | **ベースライン越え** |

**新特徴量の寄与**:
- `prev_finish_category`: 重要度ランク **5位**（MVP）
- `distance_change`: 重要度ランク **9位**

### 17.4 V14 ペース×脚質マッチング特徴量（2025-12-09追加）

データ分析により発見したパターン（逃げ馬ROI 175-189%、位置改善ROI 136%）を特徴量化。

**追加した4つの特徴量**:
1. `horse_front_runner_rate`: 逃げ馬傾向（重要度ランク**第8位**）
