## 2. なぜ競馬AIは難しいのか - 根本的な問題認識

### 2.1 競馬AI失敗の構造的要因

```
┌─────────────────────────────────────────────────────────────────┐
│                    競馬AI失敗の構造的要因                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  【問題1】控除率の壁                                             │
│  └─ JRAが約20%を控除 → 普通に買うと回収率80%に収束              │
│  └─ 「強い馬を当てる」だけでは絶対に勝てない                    │
│                                                                 │
│  【問題2】オッズへの収束                                         │
│  └─ オッズ・人気を特徴量に入れると、予測が市場に追随            │
│  └─ 的中しても期待値が1を超えない                               │
│                                                                 │
│  【問題3】過小評価の陳腐化                                       │
│  └─ 発見した「エッジ」は他者にも発見され、すぐに消失            │
│  └─ 継続的な特徴量発見・モデル更新が必須                        │
│                                                                 │
│  【問題4】複合馬券の確率計算の困難さ                             │
│  └─ 三連単は数千通りの組み合わせ                                │
│  └─ 単一モデルでは期待値計算が不可能                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 解決方針

**核心原則：「オッズに織り込まれていない情報」だけを使う**

```python
# ❌ 使ってはいけない特徴量（市場に織り込み済み）
FORBIDDEN_FEATURES = [
    'odds',              # オッズそのもの
    'popularity',        # 人気順位
    'expected_odds',     # 予想オッズ
    'betting_fraction',  # 投票率
]

# ✅ 使うべき特徴量（市場が見落としやすい）
VALUABLE_FEATURES = {
    'hidden_ability': [
        'last_3f_rank_avg',        # 上がり3F順位（展開不利でも能力は高い）
        'best_time_at_distance',   # 同距離ベストタイム
        'class_up_performance',    # 昇級初戦での走り（過小評価されやすい）
    ],
    'aptitude_mismatch': [
        'track_type_change',       # 芝↔ダート転向
        'distance_change_ratio',   # 距離変更率
        'going_preference_score',  # 馬場状態適性スコア
    ],
    'condition': [
        'weight_change',           # 馬体重増減
        'rest_days_optimal',       # 休養日数の最適性
        'trainer_recent_form',     # 調教師近走成績
    ],
}
```

## 3. 4層ハイブリッドアーキテクチャ設計

### 3.1 アーキテクチャ概要

```
┌─────────────────────────────────────────────────────────────────┐
│                    4層ハイブリッドアーキテクチャ                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Layer 1: 能力推定層（Ability Estimation）                       │
│  ├─ 目的: 各馬の「真の能力」をスコア化                          │
│  ├─ 手法: LightGBM Ranker (LambdaRank)                          │
│  └─ 特徴: オッズ・人気を完全排除した特徴量                      │
│           ↓                                                     │
│  Layer 2: 確率変換層（Probability Calibration）                  │
│  ├─ 目的: スコアを「勝率」に正確に変換                          │
│  ├─ 手法: Platt Scaling / Isotonic Regression                   │
│  └─ 特徴: レース内で合計100%になる確率を生成                    │
│           ↓                                                     │
│  Layer 3: 着順シミュレーション層（Monte Carlo Simulation）       │
│  ├─ 目的: 全馬券種の出現確率を算出                              │
│  ├─ 手法: ハービル法 + モンテカルロ法                           │
│  └─ 特徴: 三連単の全順列確率を高速計算                          │
│           ↓                                                     │
│  Layer 4: 期待値最適化層（EV Optimization & Betting）            │
│  ├─ 目的: EV > 1.0 の馬券を抽出し、資金配分を最適化             │
│  ├─ 手法: ケリー基準 + 有効フロンティア                         │
│  └─ 特徴: リスク調整済みリターンの最大化                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 Layer 1: 能力推定層

**実装**: `LeakFreeFeatureEngineerV7` + `LGBMRanker`

**マルチタスク・ランク学習**:
- Model 1: LightGBM LambdaRank（段階的関連度）
- Model 2: LightGBM LambdaRank（単勝特化）
- Model 3: CatBoost YetiRank
- Model 4: CatBoost QuerySoftMax

**関連度ラベルの生成**:
```python
# 段階的関連度: 1着=5, 2着=4, 3着=3, 4-5着=1, 他=0
y_rel = np.zeros(len(y))
y_rel[y.values == 1] = 5
y_rel[y.values == 2] = 4
y_rel[y.values == 3] = 3
y_rel[(y.values >= 4) & (y.values <= 5)] = 1
```

### 3.3 Layer 2: 確率変換層

**手法**: Isotonic Regression + Softmax正規化

```python
# キャリブレーション後、レース内で正規化
def transform(self, scores, groups):
    raw_probs = self.calibrator.transform(scores)
    result['win_prob'] = result.groupby('group_id')['raw_prob'].transform(
        lambda x: x / x.sum()
    )
    return result
```

**評価指標**:
- Brier Score < 0.20: 合格基準
- ECE (Expected Calibration Error) < 0.05: 合格基準

### 3.4 Layer 3: 着順シミュレーション層

**ハービル法による確率計算**:

```
馬単: P(i→j) = P(i wins) × P(j wins | i won)
            = P(i) × P(j) / (1 - P(i))

三連単: P(i→j→k) = P(i) × P(j)/(1-P(i)) × P(k)/(1-P(i)-P(j))
```

**JRA控除率**:

| 馬券種 | 控除率 | 払戻率 |
|--------|-------|--------|
| 単勝 | 20% | 80% |
| 複勝 | 20% | 80% |
| 馬連 | 22.5% | 77.5% |
| 馬単 | 25% | 75% |
| 三連複 | 25% | 75% |
| 三連単 | 27.5% | 72.5% |

### 3.5 Layer 4: 期待値最適化層

**期待値計算**:
```python
EV = 確率 × オッズ × 払戻率

# オッズ調整（高オッズの過大評価を抑制）
if odds > 50:
    adjusted_odds = 30 + (odds - 50) / (1 + 0.05 * (odds - 50))
elif odds > 20:
    adjusted_odds = 20 + (odds - 20) / 2
else:
    adjusted_odds = odds
```

**ケリー基準**:
```python
# f* = (bp - q) / b
# b: 純利益倍率（オッズ - 1）
# p: 勝率
# q: 敗率（1 - p）
kelly = (b * p - q) / b
kelly = max(0, min(kelly, 1)) * kelly_fraction  # 保守的に0.25
```

## 7. LeakFreeFeatureEngineerV7実装

### 7.1 設計原則

**時点考慮型（Point-in-Time）計算**:

```
2025年6月15日のレース → 2025年6月14日以前のデータのみで統計計算
2025年6月16日のレース → 2025年6月15日以前のデータのみで統計計算
```

この原則はTrain期間だけでなく**Test期間でも同様に適用**される。

**実装方法**: `cumsum() + shift(1)` パターン

```python
# 馬の累積レース数
df['horse_cum_races'] = df.groupby('horse_id')['is_win'].transform(
    lambda x: x.notna().cumsum().shift(1).fillna(0)
)

# 馬の累積勝利数
df['horse_cum_wins'] = df.groupby('horse_id')['is_win'].transform(
    lambda x: x.fillna(0).cumsum().shift(1).fillna(0)
)

# 勝率計算（最低レース数制限）
df['horse_win_rate'] = np.where(
    df['horse_cum_races'] >= min_races,
    df['horse_cum_wins'] / df['horse_cum_races'],
    np.nan
)
```

## 13. 結論と今後の課題

### 13.1 達成事項

1. **真の時点考慮型特徴量エンジニアリングの実装**
   - Test期間内でも各レース日以前のデータのみを使用
   - cumsum() + shift(1)パターンによる実装

2. **データリークの完全排除**
   - 現在のレースのタイム・上り3F・通過順は使用していない
   - 手動計算との突合で確認済み

3. **過学習の抑制**
   - Train-Test差分を9.9%に抑制（許容範囲内）
   - 強力な正則化パラメータの適用

4. **安定したROI**
   - 全体ROI 148.2%
   - 10ヶ月中9ヶ月がROI 100%超

### 13.2 今後の課題

1. **長期間バックテスト**
   - 2020年以前のデータでの検証
   - 異なる市場環境での安定性確認

2. **実運用テスト**
   - 少額での実証実験
   - リアルタイムオッズでの評価

3. **特徴量拡張**
   - 残り特徴量の統合
   - 血統詳細、ペース適性、条件適性の追加

4. **train_hybrid_v3.pyへの統合**
   - 検証済みV7の本番パイプラインへの組み込み

### 13.3 注意事項

- 過去データでの結果が未来でも同様に機能する保証はない
- 競馬市場は常に変化するため、定期的な再検証が必要
- 実運用前に必ず少額での実証実験を推奨
