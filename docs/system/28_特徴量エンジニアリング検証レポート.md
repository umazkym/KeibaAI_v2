## 1. 検証概要

### 目的

「下位×短縮」パターンを中心とした特徴量エンジニアリングの再評価および新特徴量候補の検証。

### 結論

| 項目 | 結論 |
|------|------|
| 新特徴量の効果 | いずれも本番投入は見送り |
| 市場効率性 | 公開データからの追加価値発見は困難 |
| 現行モデル | V15+V4.4（ROI 77-82%）が最適解に近い |

## 2. 分析の方法論と心がけ

> [!IMPORTANT]
> **今後の分析でも以下の方法論を適用すること**

### 2.1 すぐに結論を出さない

初期の分析結果を鵜呑みにせず、複数の視点から検証を重ねる。

**例: タイム指数の検証プロセス**
```
第1段階: popularityありで検証 → 効果+3.6%!
  ↓
問題発覚: V15/V4.4はpopularityを使っていない
  ↓
第2段階: popularityなしで再検証 → 効果+3.6%（維持）
  ↓
疑問: 過適合リスクは？既存特徴量との重複は？
  ↓
第3段階: 過適合チェック → 訓練→検証で-5.1%低下
  ↓
第4段階: 完全分離検証（2014-2021訓練、2024-2025検証）
         → 効果+1.5%のみ（大幅縮小）
```

### 2.2 過適合を常に警戒する

全ての検証で以下をチェック：

```markdown
□ 1. 訓練期間と検証期間の完全分離
     - 例: 2014-2021年で訓練、2024-2025年で検証
     
□ 2. 年度別の一貫性確認
     - 1年だけ良くても意味がない
     - 複数年で安定しているかを確認
     
□ 3. 前半→後半での劣化チェック
     - 前半期間で効果が高く、後半で低下 → 過適合の兆候
     
□ 4. 標準偏差の確認
     - 標準偏差 > 平均改善 → 効果は信頼できない
```

### 2.3 「なぜ効果があるのか」を考える

効果が見られた場合でも、その理由を深堀り：

**例: 京都1400mダートの+28.6%改善**
```
疑問1: 本当に過適合ではないか？
  → 前半(2018-2021)の改善: +7.0%
  → 後半(2022-2025)の改善: +50.2%
  → 後半でむしろ改善 → 過適合ではない可能性

疑問2: なぜこのコースだけ？
  → 2025年に+131%の異常値がある
  → これが平均を大きく押し上げている
  → 単年の異常値を除くと効果は限定的

疑問3: 年度間変動は？
  → 標準偏差51.5%と非常に大きい
  → 確実性は低い
```

### 2.4 既存の枠組みを疑う

**発見した問題**: 検証スクリプトでpopularityを使っていた

- テストスクリプトがpopularityを特徴量として使用
- しかしV15/V4.4は**popularity不使用**
- この違いを見落とすと、効果の過大評価につながる

> [!WARNING]
> **テストは本番環境と同じ条件で行う**

### 2.5 本番モデルの既存特徴量を確認する

新特徴量を追加する前に、本番モデルの特徴量を確認：

- `keibaai/models/v15/feature_names.json` - V15の特徴量（67個）
- `keibaai/models/mu_v4_4/feature_names.json` - V4.4の特徴量（70個）

**確認すべき点**:
- 新特徴量が既存と重複していないか
- 新特徴量の元データが既に使われていないか

## 3. 検証した特徴量の詳細

### 3.1 is_comeback_candidate（カムバック候補）

**定義**: `(prev_finish >= 7) & (prev_finish <= 10) & (distance_change < -200)`

**仮説**: 前走で下位に沈んだ馬が距離短縮で巻き返すパターン

| 検証項目 | 結果 |
|----------|------|
| Walk-forward改善 | **+0.0%** |
| 特徴量重要度 | 109（最下位） |
| 判定 | ❌ 効果なし |

**理由**: 
- `prev_finish`と`distance_change`は既にV15に存在
- LightGBMが非線形関係を自動で学習済み
- 明示的な組み合わせ特徴量の追加価値なし

### 3.2 prev_time_avg（タイム指数）

**定義**: 過去の上がり3Fを距離×馬場で標準化した偏差値

| 検証段階 | 結果 |
|----------|------|
| popularityあり | +3.6% |
| popularityなし | +3.6% |
| 過適合チェック | 訓練→検証で-5.1% |
| 完全分離検証 | **+1.5%のみ** |
| 判定 | △ 限定的 |

**理由**:
- V15は既に`horse_last3f_avg`を持つ
- 条件別補正は過適合リスクを増加
- 補正なし生タイムでも+1.5%のみ

### 3.3 jockey_change（騎手乗り替わり）

**定義**: 前走と騎手が異なるフラグ

| 検証項目 | 結果 |
|----------|------|
| 平均ROI差 | **-2.1%** |
| 年度間標準偏差 | ±6.5% |
| 判定 | ❌ 不安定 |

## 4. コース別モデルの検証

### 4.1 条件別分割の効果

| 分割方法 | ROI改善 | 判定 |
|----------|---------|------|
| 馬場別（芝/ダート） | -0.7% | ❌ |
| 距離別（4分割） | -1.7% | ❌ |
| 馬場×距離（8分割） | +1.4% | △ |

**結論**: 単純な条件分割は効果なし

### 4.2 具体的コース別モデル

**アプローチ**:
- 「東京1200m芝」のような具体的コースで専用モデルを作成
- 馬の**全成績**（コース問わず）を特徴量として使用

**15コースでの検証結果**:
| 指標 | 値 |
|------|-----|
| 平均改善 | +3.5% |
| 改善したコース | 8/15（53%） |

### 4.3 有望コースの8年Walk-forward検証

| コース | 平均改善 | 標準偏差 | 過適合チェック |
|--------|---------|---------|--------------|
| 京都_1400m_ダート | +28.6% | ±51.5% | 後半でむしろ改善 |
| 小倉_1700m_ダート | +5.0% | ±15.9% | 安定 |
| 東京_1400m_ダート | +0.2% | ±15.8% | 過適合兆候あり |

**京都1400mダートの詳細分析**:
```
年度別改善:
  2018: +21.4%
  2019: +10.8%
  2020: -11.1% ← 悪化
  2023: +2.6%
  2024: +16.8%
  2025: +131.2% ← 異常値

→ 2025年の+131%が平均を大きく押し上げ
→ 標準偏差51.5%と非常に大きい
→ 「確実に100%超え」とは言えない
```

**結論**:
- 特定コースでは改善の可能性あり
- ただし年度間変動が大きく確実ではない
- 実運用前に2-3年のリアルタイム検証が必要

## 5. 重要な発見：市場効率性

### 5.1 発見のプロセス

```
初期仮説: 新しい特徴量でROI改善できるはず
  ↓
is_comeback_candidate: 効果なし
タイム指数: 効果限定的
騎手乗り替わり: 効果なし
条件別分割: 効果なし
  ↓
疑問: なぜ何をやっても効果がないのか？
  ↓
分析: V15/V4.4はpopularityを使っていない
      → モデルは過去成績から独自に予測
      → しかし結果的に市場（オッズ）と似た評価に
  ↓
結論: 市場（オッズ）が非常に効率的
```

### 5.2 市場効率性のメカニズム

```
良い馬（速いタイム、好成績）
  ↓
人気が集まる
  ↓
オッズが下がる
  ↓
ROIは向上しない

→ 公開情報は既に価格に織り込まれている
→ 追加価値を見つけるのは非常に困難
```

### 5.3 V15/V4.4はpopularityを使っていない

**確認結果**:
- `keibaai/models/v15/feature_names.json`: popularity **なし**
- `keibaai/models/mu_v4_4/feature_names.json`: popularity **なし**

**示唆**:
- モデルは過去成績から独自に勝率を予測
- しかし結果的に市場評価と高い相関を持つ
- これは「市場が効率的」であることの証拠

## 6. 得られた教訓

### 6.1 機械学習に関する教訓

| 教訓 | 説明 |
|------|------|
| **LightGBMは賢い** | 人間が作る組み合わせ特徴量は多くの場合不要 |
| **データ分割は慎重に** | 分割するとサンプル減少→過適合リスク増 |
| **既存特徴量を確認** | 新特徴量が既存と重複していないか確認 |
| **非線形関係は自動学習** | 決定木系モデルは交互作用を自動検出 |

### 6.2 検証プロセスに関する教訓

| 教訓 | 説明 |
|------|------|
| **完全分離検証** | 訓練と検証を時間的に完全分離する |
| **多年度検証** | 1年だけでなく複数年で確認 |
| **前半/後半比較** | 過適合の兆候を検出 |
| **本番と同条件** | テストは本番環境と同じ設定で |
| **異常値に注意** | 単年の異常値が平均を歪める |

### 6.3 競馬市場に関する教訓

| 教訓 | 説明 |
|------|------|
| **市場は効率的** | 公開情報は価格に織り込み済み |
| **77-82%は良好** | 控除率(20%)を考慮すると優秀な水準 |
| **100%超えは困難** | 非公開情報なしでは現実的でない可能性 |
| **コース適性は例外?** | 市場が完全に織り込んでいない可能性あり |

## 7. 今後の方向性

### 7.1 短期（継続モニタリング）

- **現行V15+V4.4を継続使用**
- 有望コース（京都1400mダート等）のモニタリング
- 2-3年の実績を蓄積してから判断

### 7.2 中期（非公開データの活用検討）

| データソース | 期待される価値 | 取得難易度 |
|-------------|--------------|----------|
| 調教データ | 当日の馬の状態 | 中 |
| リアルタイムオッズ変動 | 「本命筋」の動き | 高 |
| 厩舎情報 | 仕上がり状態 | 高 |

> [!NOTE]
> `shutuba.parquet`の`morning_odds`は全件NULLで使用不可。
> リアルタイムオッズ取得の仕組み構築が必要。

### 7.3 長期（戦略の見直し）

- **ROI目標の現実的な見直し**
  - 100%超え → 安定した80-85%を維持
- **リスク管理の強化**
  - 高ROIより低変動を重視
- **資金管理の最適化**
  - ケリー基準の適用
