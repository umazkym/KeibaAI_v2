## 🎯 現状分析

### μモデルの役割

μモデル（ミューモデル）は**1着馬を予測するランキングモデル**です。

```
入力: 特徴量（馬・騎手・血統・レース条件など）
出力: 各馬のスコア（高いほど1着になりやすい）
アルゴリズム: LightGBM LambdaRank
```

### 現在の性能（v5.4ベースライン）

| 指標 | 値 | 説明 |
|------|-----|------|
| **Test ROI** | **79.43%** | 2024年以降のデータで評価 |
| 的中率 | 約32% | Top1予測が1着になる割合 |
| 投資数 | 5,709レース | Test期間のレース数 |
| 特徴量数 | 169 | 現行版の特徴量数 |

### ROIの壁

```
現状: 79.43%（約20%の損失）
目標: 100%超（利益を出す）

ギャップ: +21ポイント以上の改善が必要
```

## 🏆 目標・成功基準

### 主目標

**μモデル単体（σ/νモデル不使用）でROI 100%超を達成する**

### 成功基準

| 指標 | 必達条件 | 努力目標 |
|------|----------|----------|
| Test ROI | ≥100% | ≥110% |
| 的中率 | ≥25% | 維持または向上 |
| 投資数 | 維持（全レース） | 維持 |
| データリーク | なし | なし |

### 制約条件

1. **σモデル（確信度）・νモデル（期待値）は使用しない**
2. **馬券の絞り込み（フィルタリング）は行わない**
3. **データリーク（未来情報の使用）は厳禁**

### 重要な学び

#### 1. データリークの罠

```python
# ❌ リーク例1: 当該レースの4コーナー通過順位を使用
corner4['gap_zscore']  # 当該レースのデータ

# ❌ リーク例2: 当該レースの着順から計算
normalized_rank = 1.0 - (finish_position - 1) / (n_runners - 1)

# ✅ 正解: 過去レースのデータのみ使用 + shift(1)
horse_avg_gap = corner4.groupby('horse_id')['gap_zscore'].transform(
    lambda x: x.expanding().mean().shift(1)
)
```

#### 2. 新特徴量の重要度が低い理由

v8.2で追加した特徴量の重要度ランキング:

```
horse_avg_gap_zscore_past: rank=37, importance=80
horse_prev_gap_zscore: rank=47, importance=66
horse_closing_rate_past: rank=81, importance=31
```

**考察**:
- 既存の169特徴量がすでに高い予測力を持っている
- 新特徴量は既存特徴量と相関が高く、追加情報が少ない
- より「オルタナティブ」な情報源が必要

## 🔮 有望な改修方向性

### 方向性1: バリュー（Value）戦略

**概念**: 市場が過小評価している馬を発見する

```
市場オッズから示唆される勝率: 1 / win_odds
モデル予測勝率: predict_proba(X)

バリュー = モデル予測勝率 / 市場オッズ勝率

バリュー > 1.0 の馬 = 期待値プラスの投資対象
```

**実装方針**:
- μモデルの出力をIsotonic Regressionで確率に変換
- 確率とオッズの乖離を特徴量に追加
- 高バリュー馬への重み付け学習

### 方向性2: アンダードッグ（穴馬）特徴量

**概念**: 人気薄だが好走する馬のパターンを学習

```
穴馬候補の特徴:
- 前走着順が悪いが、条件が合えば好走
- 騎手変更でパフォーマンスアップ
- 馬体重回復で調子上向き
- 距離・馬場が適性と合致
```

**実装方針**:
- 「前走6着以下 → 今走3着以内」のパターン分析
- 条件変化時の成績改善率を特徴量化
- 騎手・調教師変更の効果を定量化

### 方向性3: 血統×条件マトリックス

**概念**: 血統ごとの条件適性を精緻化

```
pedigrees.parquetの活用:
- generation=1: 父（sire）
- generation=2: 祖父（父父、父母、母父、母母）

condition別の産駒成績:
- 父A × 芝1600m = 平均着順 3.2
- 父A × ダート1800m = 平均着順 5.8
```

**実装方針**:
- 産駒の過去成績を距離×馬場でマトリックス化
- スムージング（ベイジアン推定）で小サンプル対策
- 当該レース条件との適性スコアを計算

### 方向性4: トラックバイアス特徴量

**概念**: 開催馬場の偏りを活用

```
例: 「東京芝・開幕週は外枠有利」
    「阪神ダート・重馬場は逃げ有利」

実装:
- 当日のレース結果からバイアスを推定（過去N日間）
- 馬の脚質・枠番とバイアスのマッチングをスコア化
```

**注意**: 当日データを使う場合はリークに注意

## 🔧 具体的な改修施策

### 施策1: 確率キャリブレーション + バリュー学習

**目的**: モデル出力を真の勝率に近づけ、バリュー投資を実現

**手順**:

```python
# Step 1: ランキングスコアを確率に変換
from sklearn.isotonic import IsotonicRegression

# Validセットでキャリブレーション学習
calibrator = IsotonicRegression(out_of_bounds='clip')
calibrator.fit(valid_scores, valid_is_win)

# Step 2: Testセットで確率予測
test_probs = calibrator.predict(test_scores)

# Step 3: バリュー計算
test_df['implied_prob'] = 1 / test_df['win_odds']
test_df['value'] = test_df['pred_prob'] / test_df['implied_prob']

# Step 4: バリュー閾値でROI評価
high_value = test_df[test_df['value'] > 1.2]
roi = high_value[high_value['finish_position'] == 1]['win_odds'].sum() / len(high_value)
```

**必要ファイル**: races.parquet（win_odds）

### 施策2: 条件一致特徴量の強化

**目的**: 馬の過去成績を条件別に細分化

**手順**:

```python
# 条件定義
DISTANCE_BINS = {
    'sprint': (0, 1400),
    'mile': (1400, 1800),
    'intermediate': (1800, 2200),
    'long': (2200, 9999)
}

# 馬ごと・条件ごとの過去成績
for dist_cat in DISTANCE_BINS.keys():
    for surf in ['芝', 'ダート']:
        condition_col = f'horse_nr_{dist_cat}_{surf}'
        # 過去走の平均normalized_rank（shift(1)必須）
```

**必要ファイル**: races.parquet（distance_m, track_surface, finish_position）

### 施策3: 騎手・調教師変更効果

**目的**: 乗り替わりによる成績変動を特徴量化

**手順**:

```python
# 前走の騎手・調教師を取得
df['prev_jockey_id'] = df.groupby('horse_id')['jockey_id'].shift(1)
df['prev_trainer_id'] = df.groupby('horse_id')['trainer_id'].shift(1)

# 変更フラグ
df['jockey_changed'] = (df['jockey_id'] != df['prev_jockey_id']).astype(int)

# 騎手変更時の成績改善パターン
# 過去データから「変更後の成績 - 変更前の成績」を集計
```

**必要ファイル**: races.parquet, shutuba.parquet（jockey_id, trainer_id）

### 施策4: 血統×条件適性スコア

**目的**: 産駒の条件別成績を活用

**手順**:

```python
# Step 1: pedigrees.parquetから父IDを取得
sire_map = pedigrees_df[pedigrees_df['generation'] == 1][['horse_id', 'ancestor_id']]
sire_map.columns = ['horse_id', 'sire_id']

# Step 2: 産駒の条件別平均着順を計算
races_with_sire = races_df.merge(sire_map, on='horse_id')
sire_condition_stats = races_with_sire.groupby(
    ['sire_id', 'distance_category', 'track_surface']
)['normalized_rank'].agg(['mean', 'count']).reset_index()

# Step 3: ベイジアンスムージング
PRIOR_MEAN = 0.5
PRIOR_COUNT = 30
sire_condition_stats['smoothed_nr'] = (
    (sire_condition_stats['mean'] * sire_condition_stats['count'] + PRIOR_MEAN * PRIOR_COUNT) /
    (sire_condition_stats['count'] + PRIOR_COUNT)
)

# Step 4: 当該レース条件でマージ
```

**必要ファイル**: pedigrees.parquet, races.parquet

### 施策5: 朝オッズ vs 確定オッズの乖離

**目的**: オッズ変動を情報源として活用

**手順**:

```python
# shutuba.parquetから朝オッズを取得
odds_change = shutuba_df[['race_id', 'horse_id', 'morning_odds']]

# races.parquetから確定オッズを取得（学習には使用不可）
# → 代わりに朝オッズ自体の特徴量化

# 朝オッズのレース内順位
df['morning_odds_rank'] = df.groupby('race_id')['morning_odds'].rank()

# 朝オッズと過去成績の乖離
df['odds_vs_performance'] = df['morning_odds_rank'] - df['horse_past_avg_rank']
```

**必要ファイル**: shutuba.parquet（morning_odds）

## ⚠️ σ・νモデルとの分離方針

### μモデル改修の範囲（本方針書の対象）

| 対象 | 説明 |
|------|------|
| ✅ 特徴量追加 | 新しい特徴量の設計・実装 |
| ✅ モデル学習 | LightGBM LambdaRankの学習 |
| ✅ キャリブレーション | 出力の確率変換 |
| ✅ 評価 | ROI計算 |

### σ・νモデル改修の範囲（別方針書で対応）

| 対象 | 説明 |
|------|------|
| ❌ σモデル | 馬固有の不確実性推定 |
| ❌ νモデル | レース全体の混沌度推定 |
| ❌ EV戦略 | 期待値ベースの馬券絞り込み |
| ❌ Kelly基準 | 資金配分最適化 |

### 分離の理由

1. **μモデル単体の限界を把握**: σ/νなしでどこまで行けるか
2. **デバッグの容易さ**: 変数を減らして問題箇所を特定
3. **段階的改善**: 確実な基盤の上に次の施策を積む

## 📊 評価方法

### 評価指標

| 指標 | 計算方法 | 目標値 |
|------|---------|--------|
| **ROI** | Σ(的中オッズ × 100) / (投資数 × 100) | ≥100% |
| **的中率** | 的中数 / 投資数 | ≥25% |
| **平均的中オッズ** | Σ(的中オッズ) / 的中数 | ≥3.5倍 |

### 評価期間

```
Train: 2020年1月〜2022年12月
Valid: 2023年1月〜2023年12月
Test:  2024年1月〜現在

重要: Test期間のROIで最終評価
```

### リーク検証方法

```python
# 新特徴量と着順の相関チェック
for feature in new_features:
    corr = df[feature].corr(df['finish_position'])
    if abs(corr) > 0.5:
        print(f"⚠️ リークの可能性: {feature} (r={corr:.3f})")
```

## ⚡ リスクと注意事項

### リスク1: データリーク

**症状**: 異常に高いROI（100%超）

**対策**:
- 全特徴量にshift(1)を適用
- 当該レースの結果情報を排除
- 相関チェックを必ず実施

### リスク2: 過学習

**症状**: Valid ROI > Test ROI の大きな乖離

**対策**:
- 時系列分割の厳守
- Early Stoppingの適用
- 正則化パラメータの調整

### リスク3: 市場効率による限界

**症状**: 改善努力しても80%代にとどまる

**対応**:
- ROI 85-90%を中間目標として設定
- σ/νモデルとの統合に移行
- 複勝など他券種への戦略転換を検討
