## 3. 原因分析 (Root Cause Analysis)

調査の結果、以下の原因が特定されました。

1.  **`shutuba.parquet` の情報欠落**:
    - 特徴量生成のベースとなる `shutuba.parquet` (出馬表データ) に、`distance_m` (距離) やコース情報が含まれていません。
    - カラム一覧: `race_id`, `horse_name`, `jockey_id`, `trainer_id` 等のみ。

2.  **特徴量生成パイプラインの不備**:
    - `scripts/pipelines/generate_features.py` において、`shutuba_df` に対してレース情報（`races.parquet`）をマージする処理が欠けています。
    - そのため、`FeatureEngine` が距離やコース情報を参照しようとした際に欠損値 (NaN) となり、最終的に `0.0` で埋められています。

3.  **過去走特徴量の連鎖的欠損**:
    - 過去走特徴量（`past_N_*`）の生成にもレース情報や適切なマージが必要なため、これらも連鎖的に生成に失敗し、0になっています。

## 4. 結論と提言

現在のμモデルは、**「騎手・調教師・馬体重・馬齢・枠番」のみで予測を行っている状態**です。
距離適性、コース適性、展開、過去のパフォーマンスなどの重要な要素が全く考慮されていません。

**提言**:
1.  **パイプラインの修正 (緊急)**:
    - `generate_features.py` を修正し、学習データ生成時に `races.parquet` からレース情報をマージするようにします。
    - これにより、学習データにおいて距離やコース情報が正しく反映されます。

2.  **パーサーの修正 (恒久対策)**:
    - `shutuba_parser.py` を修正し、出馬表データ自体にレース情報（距離、コース、天候、馬場状態）を含めるようにします。
    - これを行わないと、**本番推論時（未来のレース）に距離情報が取れず、予測精度が低下**します。

3.  **モデルの再学習**:
    - データ修正後、モデルを再学習することで、性能（回収率・精度）の**劇的な向上**が見込まれます。
