## 1. エグゼクティブサマリー

### 1.1 目的

本書は、**μモデル単体でTest ROI 100%超を達成するための改修方針**を定めたものです。

### 1.2 現状

| モデル | Valid ROI | Test ROI | Valid-Test差 | 特徴 |
|--------|-----------|----------|--------------|------|
| v5.4（ベースライン） | 84.25% | 80.05% | 4.20% | リーク疑いあり |
| **v10.5（現状最良）** | **88.67%** | **81.77%** | **6.89%** | **完全リークフリー** |

### 1.3 ROI 100%達成に必要な改善幅

```
現状: 81.77%
目標: 100.00%
必要改善: +18.23pp

【参考】
- 的中率1%向上 ≒ ROI +3pp（平均配当3倍として）
- 平均配当0.5倍向上 ≒ ROI +15pp（的中率30%として）
```

### 1.4 アプローチ

| 優先度 | 戦略 | 期待効果 | 工数 |
|--------|------|----------|------|
| **1** | 穴馬発掘能力の向上 | +5〜10pp | 高 |
| **2** | 新特徴量の追加（未活用データ） | +2〜5pp | 中 |
| **3** | 学習方法の改善 | +1〜3pp | 低 |
| **4** | ベット戦略の最適化 | +2〜5pp | 低 |

## 4. 改修戦略

### 4.1 戦略A: 穴馬発掘能力の向上（最優先）

#### 4.1.1 現状の問題

モデルが1番人気を選択する理由:
1. `gap_jockey_pop_lf`等が人気順位に依存
2. 1番人気の馬は実際に強いことが多い（的中率35%）
3. 穴馬を選ぶリスク回避的な学習

#### 4.1.2 改善アプローチ

**方法1: 穴馬ブースト学習**

```python
# 穴馬（5番人気以下）の的中時に高い重みを与える
if popularity >= 5 and finish_position == 1:
    sample_weight *= 3.0  # ブースト
```

**方法2: 穴馬専用特徴量の開発**

| 特徴量 | 説明 | 期待効果 |
|--------|------|----------|
| `upset_potential` | 過去に穴馬として的中した回数 | 波乱要因の発掘 |
| `odds_drift_ratio` | 朝オッズ→確定オッズの変動率 | 資金流入の検出 |
| `underrated_jockey` | 過小評価されがちな騎手 | 市場バイアスの修正 |

**方法3: 人気別閾値最適化**

```python
# 人気別に異なる閾値でベット判断
if popularity == 1:
    threshold = 0.9  # 厳しく判断
elif popularity <= 3:
    threshold = 0.7
else:
    threshold = 0.5  # 穴馬は積極的に
```

### 4.2 戦略B: 新特徴量の追加

#### 4.2.1 race_details.parquetの活用

| 特徴量 | 計算方法 | 期待効果 |
|--------|----------|----------|
| `venue_pace_tendency` | コース別の(first_half - second_half)の平均 | ペース傾向把握 |
| `horse_pace_fit` | 馬の得意ペースとコース傾向の適合度 | ミスマッチ発見 |
| `slow_pace_upset_rate` | スローペース時の波乱発生率 | 展開予想 |

#### 4.2.2 returns.parquetの活用

| 特徴量 | 計算方法 | 期待効果 |
|--------|----------|----------|
| `horse_avg_payout_lf` | 過去単勝配当の累積平均（shift済み） | 穴馬傾向 |
| `jockey_upset_rate_lf` | 騎手の穴馬的中率 | 波乱騎手の発掘 |
| `trainer_high_payout_rate_lf` | 調教師の高配当率 | 穴馬厩舎の発掘 |

#### 4.2.3 shutuba.parquetのパース強化

```python
# career_statsのパース例
# "10戦3勝[3-2-1-4]" → wins=3, places=5, runs=10

def parse_career_stats(s):
    pattern = r'(\d+)戦(\d+)勝\[(\d+)-(\d+)-(\d+)-(\d+)\]'
    match = re.match(pattern, s)
    if match:
        runs, wins, second, third, other = [int(x) for x in match.groups()]
        return {
            'career_runs': runs,
            'career_wins': wins,
            'career_places': second + third,
            'career_win_rate': wins / runs if runs > 0 else 0
        }
```

### 4.3 戦略C: 学習方法の改善

#### 4.3.1 ターゲット設計の見直し

現状:
```python
# オッズ加重のrelevanceスコア
gain = log1p(odds) * 12.74  # 1着
```

改善案:
```python
# ROI最大化に特化したターゲット
if finish_position == 1:
    target = odds * 10  # 配当そのものを学習
elif finish_position <= 3:
    target = odds / 3
else:
    target = 0
```

#### 4.3.2 損失関数のカスタマイズ

```python
# カスタム損失: 穴馬的中を重視
def custom_loss(y_true, y_pred):
    # 高配当的中を逃すペナルティを強化
    high_odds_mask = (odds > 10)
    loss = mean_squared_error(y_true, y_pred)
    loss[high_odds_mask] *= 2.0
    return loss
```

### 4.4 戦略D: ベット戦略の最適化

#### 4.4.1 期待値ベースフィルタリング

```python
# EV = P(win) * odds
# EVが1.2以上の馬のみベット
ev = model_win_prob * win_odds
bet = ev > 1.2
```

#### 4.4.2 人気別ベット戦略

| 人気 | 閾値 | 理由 |
|------|------|------|
| 1番人気 | EV > 1.3 | 市場が効率的、厳しく判断 |
| 2-3番人気 | EV > 1.1 | バランス |
| 4番人気以下 | EV > 0.9 | 市場の非効率性を狙う |

## 6. リーク防止ガイドライン

### 6.1 リークの種類と対策

| リークタイプ | 説明 | 対策 |
|--------------|------|------|
| **Target Encoding Leak** | 全期間集計の勝率 | `expanding().shift(1)` |
| **Future Information Leak** | 当該レースの情報 | `.shift(1)`で前走まで |
| **同日レース結果Leak** | 同じ日の他レース結果 | 日付でフィルタ |
| **Validation Leak** | Valid/Testの統計使用 | Train期間のみで計算 |

### 6.2 安全な特徴量パターン

```python
# ✅ 安全: 累積統計（shift済み）
df['jockey_win_rate_lf'] = df.groupby('jockey_id')['is_win'].transform(
    lambda x: x.expanding().mean().shift(1)
)

# ✅ 安全: 過去N走（shift済み）
df['past_5_finish_mean'] = df.groupby('horse_id')['finish_position'].transform(
    lambda x: x.shift(1).rolling(5).mean()
)

# ✅ 安全: Train期間固定
train_stats = train_df.groupby('sire_id')['is_win'].mean()
df['sire_win_rate_fixed'] = df['sire_id'].map(train_stats)

# ❌ 危険: 全期間集計
df['jockey_win_rate'] = df.groupby('jockey_id')['is_win'].mean()

# ❌ 危険: 当該レースの情報
df['same_day_results'] = ...  # 同日の結果を含む
```

### 6.3 新特徴量チェックリスト

新しい特徴量を追加する際は、以下をすべて確認:

- [ ] `groupby().mean()`を使用していないか
- [ ] 集計範囲は「当該レース前」のみか
- [ ] `shift(1)`で時系列シフトしているか
- [ ] `finish_position`を直接参照していないか
- [ ] `win_odds`を予測対象と関連付けていないか
- [ ] 同日の他レース結果を含んでいないか

## 7. 検証計画

新特徴量は**1つずつ追加**してROI効果を検証:

```python
for feature in new_features:
    test_features = base_features + [feature]

    if test_roi > baseline_roi and gap < 0.10:
```

## 8. σ/νモデルとの棲み分け

### 8.1 μモデルの役割（本書の対象）

| 項目 | 内容 |
|------|------|
| 目的 | 1着予測、単勝ROI最大化 |
| 対象 | 全レースで1頭を選択 |
| 出力 | 各馬のスコア（ランキング） |
| 指標 | ROI、的中率 |

### 8.2 σ/νモデルの役割（本書の対象外）

| 項目 | 内容 |
|------|------|
| σモデル | 予測の不確実性を推定 |
| νモデル | レース全体の混沌度を推定 |
| 目的 | 馬券絞り込み、リスク管理 |
| 対象 | μモデルの予測を補完 |
| 指標 | Brier Score、ECE |

### 8.3 統合時の役割分担

```
μモデル: 「どの馬が勝ちそうか」→ 候補選択
σモデル: 「予測にどれくらい自信があるか」→ 確信度フィルタ
νモデル: 「このレースは荒れそうか」→ 波乱レース検出
```
