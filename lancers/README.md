# lancers 作業フォルダ

`lancers-design-proposal` スキルの案件置き場。ホームディレクトリ直下（`~/lancers/`）に置く。

## フォルダ構成

```
lancers/
├── README.md                        このファイル
├── _templates/
│   └── YYYYMMDD_業種_案件概要/      新規案件のひな形。コピーして使う
├── _archive/
│   ├── 採用/                        受注できた案件を移す。勝ちパターンの一次情報
│   └── 不採用/                      落ちた案件を移す。負け筋の記録
└── 20260809_整体院_開院LP/          サンプル案件（記入例つき）
```

## 案件フォルダの中身

| フォルダ | 入れるもの |
|---|---|
| `依頼内容/` | `依頼文.md`（原文をそのまま貼る）、`intake.md`（案件情報の整理） |
| `参考/` | `参考URL.md`。参考サイト・依頼者の既存サイト・過去の採用案 |
| `画像/` | `支給素材/`（依頼者からもらったもの）、`自前素材/`（自分で用意したもの） |
| `提案/` | スキルの出力先。`design.md` `tone-spec.md` `素材指示.md` `提案文.md` `見積.md` |

## 新規案件のはじめ方

```bash
cd ~/lancers
cp -r _templates/YYYYMMDD_業種_案件概要 20260812_歯科_リニューアル
cd 20260812_歯科_リニューアル
claude
```

フォルダ名は `YYYYMMDD_業種_案件概要`。日付は**提案日**（応募した日）で固定する。
受注日や納品日に付け替えない。時系列で並んだときに「いつ動いたか」が読めなくなる。

起動したら `/model` でモデルを選び、`依頼内容/依頼文.md` に原文を貼ってから
「ランサーズの案件を進めたい」と話しかける。Step 0 からフローが始まる。

## 案件が終わったら

| 結果 | 移動先 |
|---|---|
| 受注できた | `_archive/採用/` |
| 落ちた | `_archive/不採用/` |
| 提案せず見送った | 削除してよい |

```bash
mv 20260812_歯科_リニューアル _archive/採用/
```

**採用フォルダは消さない。** スキルは Phase A-1 の冒頭で `_archive/採用/` を読み、
過去に何が刺さったかを提案の材料にする。ここが厚くなるほど提案の精度が上がる。

不採用も同じ理由で残す。落ちた理由が分かっているなら
`提案/振り返り.md` に3行でいいので書いてから移す。

## 注意

- このフォルダは**ローカル専用**。リモート／クラウドのセッションでは参考サイトの取得が
  ブロックされるため、スキルの中核工程（参考サイト分析）が成立しない。
  必ずターミナルから `claude` を起動する。
- 依頼者から受け取った素材は `画像/支給素材/` から動かさない。
  加工したものは `自前素材/` に別名で置く。元データを上書きしない。
